BACKEND IMPLEMENTATION

1. Create server/middleware/quickbooksAuth.ts:
```typescript
// Middleware to get authenticated user's QB client
// Handles token refresh automatically
// Throws error if user hasn't connected QB
export async function getUserQBClient(req) {
  const userId = req.user.id;
  const user = await db.query(
    'SELECT qb_access_token, qb_refresh_token, qb_realm_id, qb_token_expires_at FROM users WHERE id = $1',
    [userId]
  );
  
  if (!user || !user.qb_access_token) {
    throw new Error('QuickBooks not connected');
  }
  
  // Check if token expired
  if (new Date() >= new Date(user.qb_token_expires_at)) {
    await refreshUserQBToken(userId, user.qb_refresh_token);
    return getUserQBClient(req); // Retry with fresh token
  }
  
  return createQBClient(user.qb_access_token, user.qb_realm_id);
}
```

2. Create server/routes/quickbooksRoutes.ts with these endpoints:

A. GET /api/quickbooks/auth-url
Returns: { authUrl: "https://appcenter.intuit.com/connect/oauth2?..." }
Logic:
- Generate OAuth URL with state = current user's ID (encrypted)
- Scopes: ['com.intuit.quickbooks.accounting']
- Redirect URI from env

B. GET /api/quickbooks/callback?code=xxx&state=xxx&realmId=xxx
Logic:
- Verify state matches current user
- Exchange code for access_token + refresh_token
- Store tokens in users table (encrypted):
  UPDATE users SET 
    qb_access_token = encrypt($1),
    qb_refresh_token = encrypt($2),
    qb_realm_id = $3,
    qb_token_expires_at = NOW() + INTERVAL '1 hour',
    qb_connected = TRUE,
    qb_connected_at = NOW()
  WHERE id = $4
- Fetch QB company info, store qb_company_name
- Redirect to /settings?qb_success=true

C. POST /api/quickbooks/disconnect
Logic:
- Revoke tokens via QB API
- UPDATE users SET qb_connected = FALSE, qb_access_token = NULL WHERE id = current_user
- Return success

D. GET /api/quickbooks/status
Returns: 
```json
{
  "connected": true,
  "companyName": "Smith Law Firm",
  "connectedAt": "2026-01-04T10:30:00Z",
  "lastSync": "2026-01-05T14:20:00Z"
}
```

E. POST /api/quickbooks/create-invoice
Body: { caseId, violationIds[], dueDate?, memo? }
Logic:
- Get current user's QB client
- Fetch violations from database
- Fetch or create QB customer from case (store qb_customer_id)
- Create QB invoice:
  Customer: linked to case
  Line items: one per violation
    Description: "{violation_type} on {date}"
    Amount: $0 (lawyer edits in QB)
    ServiceDate: violation date
  Memo: "DivorceASE Case #{caseId}"
- Log to quickbooks_sync_log
- Return: { invoiceId, invoiceUrl, qbInvoiceNumber }

F. GET /api/quickbooks/expenses?caseId=X&startDate=YYYY-MM-DD&endDate=YYYY-MM-DD
Logic:
- Get current user's QB client
- Query QB Purchase objects where Memo contains case ID or customer matches case
- Return: [{ date, vendor, amount, description, qbId }]
- Cache results for 1 hour

G. POST /api/quickbooks/expense-report
Body: { caseId, startDate, endDate, format: 'pdf' }
Logic:
- Fetch expenses using above endpoint
- Generate PDF using existing PDF generation logic
- Return downloadable file
